CORRECTED (see chip-6502#37): the FAILs in with-spec-timing-FAIL.log were caused by my testbench, not by the RTL. tb/tb_cyc6502.sv counted reset cycle 1 one clock edge too early (before the first rising edge that samples res_n = 1), so the RTL's first SYNC looked like cycle 9 instead of 8. Igris ruled (#37) that the spec's definition of cycle 1 (#30) is the intended one and that the RTL is right. The counter was fixed (commit 7792fe3); with it, the same 12 runs pass with the spec's default timing (logs/rtl-run7). The '+SYNC_CYCLE=9 +VEC_CYCLE=7' run (with-rtl-timing-PASS.log) only shows that the old counter's view was consistently one early; it is kept as history, not as a statement about the RTL.
